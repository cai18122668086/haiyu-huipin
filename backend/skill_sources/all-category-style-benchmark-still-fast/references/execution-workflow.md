# Execution workflow

The executable state authority is `scripts/workflow.py`; `entrypoint.py` only parses commands and persists receipts. Every mutation writes `artifacts/workflow.json` and a compact `style-harness.json`.

The first operational action is always `new` (or `resume` for an existing run). A file read, `--help` call, code search, verbal plan, or direct provider call does not activate this workflow. Do not call the image provider until `audit-plan` has passed and the active `generation-request-*.json` exists. `new` registers immutable product and benchmark files with SHA-256. Mixed `--input` uploads are stored as `unassigned`; `inspect-inputs` must bind every image to exactly one role using a hash-matched visual review before route classification. Upload order and filenames are not role evidence. `compile-reference-crops` accepts only physical crops reviewed as `style_mechanism_only`, `layout_only`, `color_only`, or `human_action_only`; raw benchmark files are analysis-only. `compile-visual-passport` records eight mechanism observations. `register-product-facts` rejects inferred safety, performance, medical and certification claims. `plan-target-page` requires one ordered unit row per route contract and a translation for every source semantic. `audit-plan` is mandatory before a generation token.

For `CAROUSEL_SET` runs with multiple benchmark references, crop compilation requires complete coverage and contiguous `source_order`. The route plan then binds ordered `source_reference_ids` and `narrative_role` values to the target units; omitted or reordered benchmark pages fail before generation.

Every route also requires set-level `source_content_analysis`: all visible source text is transcribed per panel, each panel receives a content role and normalized message, and the complete persuasion method is recorded as conversion stage, buyer question, persuasion job, belief shift, evidence obligations and visible expression actions. Adjacent panels also require semantic handoffs and the next buyer question. This prevents the planner from replacing the benchmark's story with facts selected only from the current product. For detail Pair generation, the request narrows the reference attachments to the current target's ordered source steps and records them as `target_reference_sequence`; a long non-fixture sequence that repeats one method template across distinct panels fails before generation.

Reference preparation uses `init-reference-analysis` and `crop-reference-panels` before compilation, as specified in [reference-analysis.md](reference-analysis.md). The latter materializes source-bound analysis-only full-panel crops after the agent observes boundaries; it cannot infer or certify unknown panels. Compilation rejects reused panel files, mismatched pixels and hashes, missing source coverage, or full panels offered as style-only generation crops. Passport errors enumerate exact missing/unknown/empty mechanism keys and invalid source citations; per-panel content must cover every physical panel in reading order. Route planning covers every source content step on all routes.

Generation is serialized in declared order. The request contains product image hashes, sanitized crop hashes, all translation fields, route geometry, and a single-use token. The token is committed before the request is handed to the artflow provider, and an atomic recovery manifest records the request and prompt hashes. It also requires high-quality native rendering at the exact route canvas with text and imagery generated together; post-text overlays and low-resolution upscaling are prohibited. Artwork must exist, match the route canvas, and be recorded before audit. Non-fixture audit evidence must repeat the artwork SHA-256 and supply scored style/product evidence. A failed unit has one revision opportunity; a second failure is `GROUP_FAILED_CONTINUE` and is barred from strict finalization. Delivery uses the accepted ordered list and exact detail centerline slices.

`generation_scope` and `current_target_plan` specify the current job only. Detail jobs default to one two-screen vertical master; see [detail-pair-execution.md](detail-pair-execution.md). The readable imagegen prompt is generated from that same request. New generation requests cannot overwrite or skip an awaiting artwork, audit, or required revision. Input/crop SHA-256 is rechecked before issuing a token. The benchmark controls fact selection and expansion; there is no default exactly-once priority-fact coverage rule. The last unit's internal closing duty is never visible copy. `scripts/artflow_render.py` is the only permitted bridge to the image provider; it additionally requires the persisted workspace, a passing plan audit and the active target request. A failed plan or persisted `generation-block.json` therefore cannot fall through to a manually composed image prompt, even if workflow state was incorrectly changed. Every current Pair source step must have a matching sanitized crop; generic mechanism crops and crops without explicit source-step/product-pixel exclusion are rejected for non-fixture runs. `resume` validates the atomic recovery manifest and exposes `resume-imagegen-request`; that command returns the exact existing handoff without promoting state or minting a token. A missing or changed artifact fails closed. Tool capacity failures remain external and do not authorize a single-screen shortcut.
If one source step is expanded over multiple target units, follow the observed benchmark expansion. Repetition is allowed when the reference repeats it; differentiation is required only when the reference differentiates it. There is no default source-expansion-note requirement.
When multiple product-original inputs are present, `register-product-facts` records an `evidence_inventory` row for each input as an available optional source. An input may remain unused when the mapped benchmark step does not call for it.
Copy compliance is tiered: ordinary descriptions such as confirmed material, color, texture, size, capacity and usage need no external test report; quantified, patent, certification, inspection, ranking, comparison and strong safety/efficacy claims need bound evidence; category-sensitive medical or efficacy wording receives category review; only clearly prohibited guarantees or deceptive authority claims fail automatically.

Before recording real output, build a local receipt using `scripts/render_provenance.py` and the original path returned by the tool plus its unchanged artwork copy. Detail CLI recording requires `--render-receipt`; every non-fixture image audit rechecks the original bytes and dimensions. The receipt is not signed by the provider. The original file must remain available through audit. A fixture cannot override a failed real review; the final visual-quality label depends on every accepted target and the global review.
