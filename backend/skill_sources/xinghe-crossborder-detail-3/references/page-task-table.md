# Page Task Table

Create a `Page Task Table` before writing prompts. It is the control sheet for the full detail-page set and must be built from the `Module Plan` in `page-planning-strategy.md`.

The number of rows in this table is the final generation count unless the user explicitly specified a different count.

## Required Columns

Each screen must define:

- screen number and page role;
- purchase decision type;
- module title direction;
- buyer demand solved by this screen;
- buyer question;
- core information;
- matched product selling point;
- confidence level: confirmed, reasonable inference, or needs confirmation;
- direct English headline direction;
- selling-point label direction;
- copy suggestion in the buyer-facing language;
- scene or information structure;
- visual suggestion;
- visual proof method;
- required proof or visible evidence;
- subject scale;
- required elements;
- forbidden elements;
- risk reminder;
- difference from the previous screen.

## Default Eight-Screen Rhythm

Use this rhythm unless the `Module Plan` selects a better count, the user specifies another count, or the platform profile calls for a different order:

1. `Impact Cover`: communicate the strongest purchase reason.
2. `Core Demand`: answer the highest buyer concern with the most direct selling point.
3. `Scene Proof`: show the product in a realistic use, style, or ownership scene.
4. `Detail Evidence`: material, structure, texture, craft, ingredient, interface, or local proof.
5. `Objection Handling`: comparison, annotation, FAQ, problem-solution, or information card.
6. `Use Process`: operation, pairing, wearing, preparing, opening, cleaning, storing, or daily flow.
7. `Info Confirmation`: parameters, visible packaging data, checklist, size, care, compatibility caveat, or package contents.
8. `Closing Summary`: summarize purchase reasons without fake urgency or consultation-style CTA copy.

Compress or expand this rhythm when the planned or requested image count differs, while preserving demand variety and layout variety.

If `page-planning-strategy.md` selects a best hero direction based on purchase decision type and platform, use that decision for module 01 instead of offering multiple first-module options.

## Main Image Separation

Only the first screen may feel close to a product main image. Other screens must explain, prove, compare, demonstrate, or contextualize. Do not create a set that only changes backgrounds, titles, or product angles.

## One-Screen Rule

Each screen must solve one buyer demand. Do not combine multiple unrelated claims on one screen. If two claims compete, choose the one with higher purchase impact.

## No Material Reshoot List

Do not output a separate material reshoot list. Missing proof, missing parameters, or unavailable assets should appear only as module-level `risk reminder` items or final optional review notes.
