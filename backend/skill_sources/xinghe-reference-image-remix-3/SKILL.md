# 星河参考图二创3.0

将“参考图/竞品图 + 用户产品图 + 可选卖点”转化为一张新的电商主图。核心目标是：锁定参考图的商业结构和视觉骨架，替换为用户产品，并在品牌、文案和产品事实层面完成合规二创。

## Core Rules

- 默认直接生成图片：用户给出参考图和产品图，并要求参考、二创、复刻、替换产品、做主图时，直接进入最终生图流程；只有用户明确说“只要提示词/不要出图/prompt only”时才输出提示词。
- 生图工具优先级：优先使用 `$env:XINGHE_IMAGE_GENERATOR`，其次使用 `%LOCALAPPDATA%\ApiCodexOneClick\tools\generate-image.ps1`，最后才使用内置 `image_gen` 兜底。
- 部署 helper 解析顺序：先使用 `$env:XINGHE_IMAGE_GENERATOR`；如果该变量不存在，再使用 `%LOCALAPPDATA%\ApiCodexOneClick\tools\generate-image.ps1`。有参考图走 helper 的 `-ReferenceImage`，纯文案不传 `-ReferenceImage`，并保存生成结果到本地。
- 默认数量：用户未指定数量时生成 1 张。
- 默认画幅：跟随参考图比例、画幅、信息密度；用户指定平台或尺寸时优先按用户要求。
- 全品类兼容：适用于服饰鞋包、美妆个护、食品饮料、家居百货、3C数码、母婴宠物、户外运动、工业配件、保健营养、珠宝配饰、玩具礼品、虚拟产品包装图等。
- 产品一致性最高：用户产品图是唯一产品事实来源，必须保留外观、颜色、结构、材质、纹理、包装、logo、印刷文字、配件和关键细节。
- 参考锁定优先：除非用户要求改风格，否则锁定参考图的排版、构图、字体风格、景别、光影效果、色调、信息层级和点击逻辑。
- 合规优先：不得复制竞品品牌、logo、认证、销量、排名、评价、检测报告、医疗功效、绝对化承诺或用户未提供的强证明。

## Required Inputs

- 参考图/竞品图：用于锁定排版、构图、字体风格、景别、光影、色调、文案节奏和点击逻辑。
- 用户产品图：作为新图中产品外观和细节的唯一视觉依据。
- 可选卖点：用户给出的卖点、目标人群、平台要求、尺寸、数量、语言或活动主题。

如果缺少参考图或产品图，简短要求用户补充缺失图片，不要生成。

## Locking Requirements

在生成提示词中明确锁定以下内容：

- 排版锁定：保持参考图的主标题位置、产品区位置、卖点模块数量、视觉阅读顺序、留白比例、边距感和信息密度。
- 构图锁定：保持主体大小关系、产品朝向逻辑、前中后景关系、对角线/中心/左右分栏/上下分层等构图方式。
- 字体锁定：保持参考图的字体气质、粗细层级、字号比例、字距观感、描边/阴影/高亮方式；不得复制竞品原文。
- 景别锁定：保持参考图的镜头距离和视角，例如特写、半身、全景、俯拍、平视、低角度、微距、包装陈列或场景化远近关系。
- 光影锁定：保持参考图的主光方向、光比、阴影硬度、高光形态、反射质感、氛围光、背景渐变和商业摄影质感。
- 风格锁定：保持参考图的整体电商设计风格，例如高端极简、强促销、测评对比、场景种草、科技感、清新自然、节日活动、礼盒氛围等。

## Workflow

1. 识别输入角色：
   - 参考图：学习并锁定视觉骨架和点击逻辑。
   - 产品图：提取并保留用户产品事实。
   - 文本要求：卖点、平台、尺寸、数量、语言、是否只要提示词。
2. 拆解参考图：
   - 画幅比例、排版网格、主体位置、文字区域、装饰模块；
   - 产品景别、镜头视角、焦点路径、前后景层次；
   - 字体风格、标题层级、短文案节奏、标签样式；
   - 光影方向、色调、材质表现、背景质感；
   - 点击理由和买家情绪。
3. 拆解用户产品图：
   - 品类、形状、结构、颜色、材质、包装、logo、图案、配件；
   - 必须保留的关键细节；
   - 从图片和用户卖点中可以安全表达的内容。
4. 生成新图提示词：
   - 锁定参考图的排版、构图、字体风格、景别和光影效果；
   - 将参考图中的产品替换为用户产品；
   - 文案改写为用户产品相关内容；
   - 去除竞品品牌和不可证明元素；
   - 让新图看起来像同一视觉模板下的原创商用图，而不是简单贴图。
5. 根据用户要求执行：
   - 用户要 prompt only：只输出最终提示词；
   - 否则：优先使用部署工具 helper 生成图片；有参考图默认走 edits，纯文案起图走 generations。
   - 如果 helper 不存在、不可用、执行失败，或无法保存/展示结果：使用内置 `image_gen` 作为最终兜底。

## Category Adaptation

根据品类自动调整表达，不改变参考图核心视觉骨架：

- 服饰鞋包：优先保留版型、面料、穿搭比例、模特姿态或陈列景别。
- 美妆个护：优先保留瓶身/盒身质感、膏体/水光/肌肤场景、精致光影。
- 食品饮料：优先保留包装、食材、口味氛围、食欲光泽，不虚构营养或功效。
- 家居百货：优先保留使用场景、尺寸关系、材质触感、功能可视化。
- 3C数码：优先保留结构接口、屏幕/灯效/金属质感、科技光影。
- 母婴宠物：优先保留安全温和的视觉氛围，不虚构认证或医学效果。
- 工业配件：优先保留结构精度、材质、规格感、应用场景，不编造参数。
- 保健营养：只表达用户提供或包装可见的信息，不生成疾病治疗暗示。

## Copy Rules

- 学习参考图的文案节奏和信息层级，不复制原文。
- 文案必须围绕用户产品和用户提供的卖点改写。
- 没有卖点时，只根据可见产品事实和常见购买关注点保守表达。
- 缩短文案，适配电商缩略图阅读。
- 不虚构认证、销量、排名、价格、检测、功效、适用人群或结果承诺。

## Product Fidelity Lock

每次生成都要包含以下约束：

```text
以用户上传的产品图作为唯一产品事实来源。保持产品外观、轮廓、结构、尺寸比例、颜色、材质、纹理、光泽、包装、logo、印刷文字、图案、配件、边缘形状和关键细节一致。不要新增不存在的logo、标签、认证、按钮、配件、纹理、包装文字或功效声明。细节不清楚时保留可见设计，不要重新发明产品。产品一致性优先于美观、戏剧化和创意风格。
```

## Generation Tool Priority

默认优先使用部署工具写入的 helper。只有在 helper 不存在、不可用、执行失败，或无法把结果稳定保存为本地文件并在对话中预览时，才使用内置 `image_gen` 作为最后兜底。不要使用 SDK 默认 key 或本地绘图脚本作为替代。

部署 helper 解析顺序：

```text
$env:XINGHE_IMAGE_GENERATOR
%LOCALAPPDATA%\ApiCodexOneClick\tools\generate-image.ps1
```

接口和路由规则：

- 有产品图、参考图、竞品图等参考图片时，调用 helper 并通过 `-ReferenceImage` 传入所有参考图片；helper 会路由到 `https://xinghe.xin/v1/images/edits`。
- 没有参考图片、纯文本起图时，不传 `-ReferenceImage`；helper 会路由到 `https://xinghe.xin/v1/images/generations`。
- 模型固定使用部署工具配置的 `gpt-image-2`。
- API Key 使用部署工具安装时校验并写入的 key，不向用户询问，不在回复中输出、保存或复述真实 key。
- 完整生图提示词必须先写入 UTF-8 prompt 文件，再用 `-PromptFile` 调用；不要把长提示词直接拼到命令行。
- 每张图单独调用一次，保存到本地输出目录。
- 生成后必须返回本地绝对路径和 Markdown 图片预览；最终回复必须使用本地绝对路径展示图片。

PowerShell 示例：

```powershell
$helper = $env:XINGHE_IMAGE_GENERATOR
if (-not $helper) { $helper = Join-Path $env:LOCALAPPDATA 'ApiCodexOneClick\tools\generate-image.ps1' }
$promptFile = "<absolute prompt file path>"
powershell.exe -NoProfile -ExecutionPolicy Bypass -File $helper `
  -PromptFile $promptFile `
  -ReferenceImage "C:\path\to\product.png", "C:\path\to\reference.png" `
  -OutputDir "<absolute output directory>" `
  -Size "1024x1024" `
  -FileName "image-01.png"
```

无参考图时删除 `-ReferenceImage ...` 参数。

如果 helper 不存在或执行失败，不要改用 Pillow、matplotlib、SVG、canvas 或占位图。只有当前会话明确暴露可用的内置 `image_gen` 时才使用它作为最后兜底；否则报告 helper 缺失或执行失败。

## Response Style

生成前只说一句：

```text
按【星河参考图二创3.0】处理：锁定参考图的排版、构图、字体、景别和光影，用你的产品完成替换生成。
```

生成后简短说明：

- 已生成数量；
- 画幅选择；
- 锁定了哪些参考图元素；
- 替换和合规处理了哪些内容。

## Validation Scenarios

- 参考图 + 产品图 + 卖点：生成锁定排版和光影的新主图。
- 参考图 + 产品图，无卖点：根据可见产品事实保守改写文案。
- 只要提示词：输出完整生成提示词，不调用生图接口。
- 缺少参考图或产品图：要求用户补图，不生成。
- 参考图含竞品 logo、认证、销量或评价：保留版式逻辑，删除或替换为用户可证明内容。
