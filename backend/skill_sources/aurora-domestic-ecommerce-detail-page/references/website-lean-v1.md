# Website contract WEBSITE_LEAN_V1

This is an explicit opt-in website contract. It does not rewrite historical plans,
reports or provider messages. The ordinary standalone v4.3.1 workflow is unchanged.

The website planner authors one `claim_coverage` array. Each primary fact declares
its evidence ceiling, actual module/job associations and short rationale once.
Depth, scheduled/dedicated module sets and recall are deterministic views of that
same source. Native primary-depth, source, formula, fact and story validation still
applies. Missing mappings remain errors; never create jobs from a claim's number,
topic or a generic screen template.

Only currently needed planning references and current-pair context enter each model
request. Product identity, relevant facts, campaign DNA, the full compact spine and
the selected pair's internal seam remain available. Duplicate machine views are
not model homework.

An approved website plan seals the profile in its root and every expanded screen.
Generation requests carry that profile inside the signed request. Pair audits use
`pair-judgment-website-v1.schema.json`. Each fixed slice has six concrete checks:
identity, facts, legibility, approved plan fidelity, composition/continuity and proof
integrity. Joint pair duty, information progression, copy binding and seam evidence
remain required. Keep observed OCR, actual presence, fact-bound content, material
omissions, brand scope and visible identity comparisons. Hashes, dimensions and
fixed crops are still verified mechanically.

Do not request the former 44 repeated per-slice checks, aesthetic scores, headline
ranks, layer counts or multiple explanations of the same issue. Minor decoration
and spacing are advisory. Product drift, fabricated facts/proof, essential illegible
copy, absent selling-point payload, broken geometry, severe layout regression and
destructive seams are material. Inspect actual pixels; no expected value, default
PASS or plan-derived observation may stand in for a visual finding.

One pair still has one initial render and at most one automatic repair. Keep both
attempts and disclose material residuals after the second attempt. Unknown provider
outcomes and incomplete observations stop processing. Finalization preserves the
exact original provider receipts, accepted audit bytes and canvas/slice lineage.
