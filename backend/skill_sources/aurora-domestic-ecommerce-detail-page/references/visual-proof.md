# Visual proof

Use this file with `visual-expression-routing.md`. Visual proof defines what can prove a claim; expression routing defines how that proof becomes a scene, action, composition and minimum necessary copy.

## Observability routing

| Claim class | Preferred proof | Copy responsibility |
|---|---|---|
| Directly visible | product, component, material, contents, interface, package macro | Name or qualify |
| Action-demonstrable | hand operation, adjustment, opening, extraction, installation, cleaning, switching | State step and result |
| Scene-expressible | credible user/product relationship and environment | Explain audience and value |
| Comparable | same product in different states, scale relation, verified structural difference | State comparison conditions |
| Text-verifiable only | battery, decibel, certification, warranty, price, test value | Preserve exact number and condition |
| Unsupported | none | Delete |

## Proof-building chain

Use:

`lead claim -> buyer benefit -> strongest current-product evidence -> evidence/action/scene relation -> camera and spatial amplification -> concise factual qualifier`

When copy is hidden, the viewer need not infer the exact sentence, but should still perceive the value family.

## Visual-proof contract

Before generation, each module must define:

- `buyer_takeaway`: what the buyer should understand;
- `visual_verb`: the visible action such as cools, folds, locks, pours, fits, opens, shields or compares;
- `primary_subject`: the product or decisive component;
- `supporting_subjects`: hands, airflow path, ingredient, environment, scale object, result state or evidence panel;
- `required_relations`: the visible source-action-result or condition-choice relationship;
- `minimum_visual_payload`: normally at least three;
- `visual_specificity_anchor`: details that make the screen belong to this product;
- `allowed_metaphor`: only when it does not pretend to be physical evidence;
- `hidden_copy_test`: what remains understandable with all promotional copy covered.

The expression contract must separately define:

- `product_presence_policy`: `REQUIRED_DOMINANT`, `REQUIRED_SUPPORTING`, `IDENTITY_TOKEN_ONLY`, `OPTIONAL`, `ABSENT_ALLOWED` or `ABSENT_PREFERRED`;
- `evidence_subject_policy`: whether the product, claim object, action/result or scene owns the first visual rank;
- `visualization_mode`: direct observation, non-diagnostic conceptual visualization, or contextual-only expression;
- `transformation_required` and `transformation_stages`: the visible beginning, action/path and end state when the claim depends on change;
- `truth_boundary`: what the concept must not imply.

Product recognition is managed across the whole page. A dedicated proof screen may contain no product at all when the adjacent sequence preserves identity and the screen is more persuasive with the claim object and transformation enlarged. Do not add a packshot merely to satisfy continuity.

For invisible or microscopic claim objects, conceptual visualization is permitted and often required. Render the object as an obviously designed commercial illustration or stylized 3D form, then show a readable state change. Never present it as a microscope view, test result, diagnostic image, exact biological morphology or verified internal mechanism unless that evidence is actually supplied. Conceptual visualization explains the claim; it does not upgrade its evidence ceiling.

Count effective visual payload only when it contributes meaning: product/component, action/path, visible result/scale/feedback, material macro, or a product-bound environment. Decorative ice, snow, glow, arrows, gradients and generic icons do not count.

## Density is multidimensional

Plan these independently:

- copy density;
- visual payload density;
- proof-relation strength;
- commercial energy;
- whether the screen is an intentional breathing screen.

For a normal domestic-commerce detail module, use a compact information ladder rather than defaulting to one headline and a few badges. Ordinary explanatory screens should usually carry 3–5 concise units: conclusion, buyer-facing explanation, bound proof/parameter/use labels, and an optional condition or selection qualifier. Hook, scene, result and closing screens may remain at 2–4 units when the image carries the missing meaning; only approved breathing screens may be sparser. Copy density must still pair with medium/high visual payload, a strong proof relationship and standard/high commercial energy. More copy is not permission for a text wall, equal-card grid or generic packshot background.

## Visible-copy whitelist

Declare every promotional phrase in `visible_copy` with its semantic role and visual anchor. The generator may render only each item's exact `text` plus text already printed on the verified product packaging. Keep roles, anchors, bindings, source explanations and layout notes machine-side; do not phrase them as candidate pixel text. Do not send internal IDs, page order, workflow transitions, design enums, page duty, buyer questions, prompt notes or repair diagnoses to the image model.

## Strong visual devices

Prefer:

- scale, macro and sectional relationships;
- visible contents or material behavior;
- hands performing a real operation;
- same-product before/after states when truthful;
- credible scenes with clear product use;
- spatial depth, controlled motion and sensory lighting;
- commercial visual rhetoric grounded in real product evidence.

Do not substitute proof with arrows, icons, glows, snowflakes, empty gradients, an unrelated model, a package close-up or a large headline alone. A diagram may clarify evidence but cannot create evidence. If a visualizable claim is led by a static packshot while the claim object appears only as a label or tiny badge, reject the screen.

## Composition freedom

The Agent may choose camera, product occupancy, crop, perspective, foreground, background depth, subject relation, layout family, reading path, lighting and short copy. The plan constrains the conclusion and evidence direction, not one frozen sketch.

Text must attach to the visual relationship it explains. Do not automatically place a display title at the top or center when an object label, path annotation, comparison caption, numeric hierarchy, scene caption or near-textless proof would communicate more directly.
