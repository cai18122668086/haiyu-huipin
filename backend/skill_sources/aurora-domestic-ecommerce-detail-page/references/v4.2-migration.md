# v4.2 migration note

v4.2 intentionally does not mutate or silently resume v4.1 sessions. The new input claim-risk contracts, request fingerprints, generation ledger, artifact-bound judgments and delivery authorization mode must exist before generation starts.

For an unfinished v4.1 campaign, preserve the raw product evidence and user-approved intent, then start a new v4.2 session, recompile the plan under current schemas and obtain a fresh approval fingerprint. Existing raster candidates may be recovered only when they belong to a v4.2 request issued by that new session; do not copy tokens or edit the session JSON.

Finalized v4.1 manifests remain historical deliverables and do not need rewriting.
