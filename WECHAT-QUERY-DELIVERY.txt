确认方式
微信下单、查单使用现有商户私钥签名，微信应答使用已配置公钥验签。
POLARIS_CREDIT_WECHAT_CONFIRMATION_MODE=query
POLARIS_CREDIT_PAYMENT_RECONCILIATION_ENABLED=true
两个参数只在绘品 API 服务启用；未修改海宇原平台、原商户或原 APIv3 密钥。
加密回调验签通过后只作通知提示，通知本身不会发放积分或确认退款。
支付和退款均以服务端向微信查询的结果为依据，浏览器返回不能标记付款。

自动补单
API 独立维护任务每 5 秒启动一轮；每轮最多 20 笔、4 路查询。
新订单按 10 秒/30 秒核对，久未支付的订单逐步延长间隔；网络异常持续重试。
数据库记录租约、下次查询、上次结果、错误和次数，进程中断后租约到期可接续。
没有在内存中丢失的临时队列；不依赖用户保持页面打开或点击“我已付款”。
对下单结果不明、订单不存在等情况不猜测成功，不随意放弃可能已付款的订单。
仅在验签且商户、应用、订单和金额一致，并确认支付成功后发放积分或会员。
重复查单、并发回调及重试都复用原订单账务事务，不会重复发放。
微信明确返回关闭/撤销等终态时停止查单，客户界面显示订单已关闭。

后台与客户界面
后台显示补单运行状态、最近完成时间、待核对和异常数量。
支付订单显示查单次数、上次/下次查单时间、渠道状态与错误码。
支持“仅看补单异常”筛选和管理员手工查单；不能人工伪造已支付。
客户订单说明后台持续核对，关闭页面也继续处理；已关闭订单引导重新购买。

验证与边界
真实微信接口：生成测试二维码，验签查单确认 NOTPAY，随后关单并确认 CLOSED。
测试二维码没有向用户展示，没有执行实际付款或真实客户退款。
隔离 PostgreSQL 与合成回归覆盖主动补单、页面关闭、网络超时、进程中断、并发回调、
金额/商户/订单不符、已关闭订单、永久幂等、退款和会员发放。
隔离金融/账户回归共 160 项通过，另通过 7 项认证回归、TypeScript、构建、定向 ESLint、Ruff 与 Mypy。
运行中的 591 个后端文本文件和 581 个前端构建文件与本工作区一致。
具体测试与生产检查结果见 verification/wechat-*.json 及 wechat-query-postgres.log。

运行注意
自动补单心跳是金融链路运行信号；若后台显示异常，先检查 API 进程和数据库，
随后对错误订单重新查单。不要通过直接修改 paid 或余额来代替渠道核对。
原 APIv3 解密配置问题仍作为历史事实保留；主动查单模式不会使用错误的 41 字节值。
若后续改回回调解密模式，应先取得当前商户正确密钥并完成专门验收。
