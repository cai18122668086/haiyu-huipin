# 公共等待反馈设计与验收边界

2026-10-22 核对。此改动基于公共上传 PR #88，以独立 PR 交付，不合并、不发布生产。

公共产品图、模特换姿势、局部改图、commerce 三入口、灵感组合器和任务详情使用共享反馈。阶段取自稳定的任务状态和已知公共 stage；未知内部 stage 用通用文案，原生复刻与详情专用协议本轮不改。已有任务确认、最终检查、失败项重试和 Amazon 审核异常语义保持原流程。

初始进度尚未上报时，用不确定动画表达活动并显示真实已完成项数；上报非零进度后显示该值。计时器只更新用时，绝不推进百分比或完成数。暂停/终态停止活动动画；有完成时间的终态用时固定，不随刷新增长。浏览器离线或轮询失败显示保留的任务状态和重新读取入口，重新读取不创建任务。失败原因可展开查看，原有重试及详情操作保留。动画支持 prefers-reduced-motion，计时器不进入实时朗读区。

参考了 [Radix Progress 官方文档](https://www.radix-ui.com/primitives/docs/components/progress) 的确定/不确定状态和 progressbar 语义，核对 [GitHub MIT 许可](https://github.com/radix-ui/primitives/blob/main/LICENSE)；也查看 [shadcn Skeleton](https://ui.shadcn.com/docs/components/skeleton) 的加载占位用途。没有复制源码或新增这些依赖；实现使用既有 React、CSS 和 lucide-react。W3C [Meter Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/meter/) 明确任务进度应使用 progressbar，而不是 meter。

验证应包含：排队/规划/生成/检查/整理、零进度长等待、真实完成项更新、部分成功/失败/取消/完成、等待人工操作、刷新恢复用时、网络失败与恢复、只刷新状态不重复提交、手机布局与静态/减少动画。原生复刻和详情的最终状态协议、全站生产速度及真实生图质量需要后续统一集成验收。


最终本地验证：生产构建、TypeScript、变更文件 ESLint、175 项前端测试通过。新增 8 项测试覆盖状态优先级、真实完成数、计时与刷新、UTC 无时区旧时间戳、异常时间、格式和实际服务端渲染可访问性。浏览器使用隔离 SQLite、关闭自动处理、合成素材与可控 503 模拟，验证了排队/规划/生成/检查/整理、恢复连接、完成后刷新用时固定、部分成功/失败原因展开、商品图与任务详情一致、Amazon 21 项及 390px 无横向溢出。无真实生图质量或生产验收声明。

实际验收发现 SQLite/旧记录可能返回没有偏移的 UTC 时间戳；已按后端 utc_now 存储规则补 UTC 解析，带 Z/明确偏移的时间仍按原值解析。计时不显示预计剩余时间。
