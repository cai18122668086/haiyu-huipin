# 一比一复刻精简接入试点（exact-compact-v2）

目标是让普通页面的一次提交自动完成规划、生图、审图、历史恢复及原图交付。
脚本代提交、聊天中的人工选择、手工修正模型契约或修改任务状态都不能算端到端通过。

## 职责边界

- 模型：源图观察、逐屏设计、区域文案绑定、像素审查和一次定向修复。
- 阶段 MD：只定义视觉职责、事实优先级和质量标准；不装载桌面操作指令或校验器源码。
- 服务端：源文件和哈希、编号、画幅、物理顺序、状态机、有限重试、原图存储与下载。

保留现有不可变 Skill 包及其已验证的后端状态守卫。模型不再阅读完整 Skill、参考文档
及 Python 源码。新适配器将精简视觉结果转换为守卫需要的内部格式，不能伪造视觉结论。

规划时一起返回区域文案与事实适配绑定。已通过模块在方案修订时保持不变，仅替换失败模块；
服务端保留未改变且依赖完全一致的真实审查结果。跨屏一致性由共享事实、源顺序、邻屏摘要
和完整计划守卫约束，不增加每轮重复推翻局部结论的整组视觉审查。模型不用复制路径、哈希、画幅和版本常量。协议自身必须有版本和内容
哈希，随快照冻结；旧快照继续使用原接入，不能静默切换。

拆屏先定位完整参考列，再只看列裁图找内部边界。独立清点步骤只看原参考和列裁图，
不接收前一步的切线、标题列表或屏数。程序比较两份观察，至多定向重拆一次，并重新
盲查；仍不一致就停止在规划前。边界坐标映射、完整覆盖和编号由程序完成，不写死
每列几屏，也不要求用户选择屏数。渐变、配色连续时仍须识别新的主标题与购买问题。

方案审查发生在生图之前，比较真实参考像素与文字提案；成图像素由后续独立审图阶段验收。
程序将每份提案、适用身份检查和画幅绑定到对应参考屏，审查模型只返回给定参考编号，
不再同时处理参考编号和生成模块编号。响应数量、编号集合与顺序仍由程序严格检查。

每次首次视觉方案审查只附一屏参考和商品原照，按源顺序逐屏完成后汇总为完整原生审查，
避免多屏载体、人物动作和文字层级串位。任一屏失败仍不能进入整套生图。修正请求包含失败屏
上一版的完整提案、身份范围与文字绑定；初稿之后最多两轮定向修正，只重新审查变化的输入。
未改变的失败提案不得重新取判定。每条获准文案必须完整绑定到现有区域，不能只在说明中
新增未绑定标题，也不能扩展区域来装入多余文案。通过模块仍由服务端冻结。

模型返回的所有位置使用具名 `rect: {x, y, width, height}`，避免四数字数组被解释成
两种不同坐标约定。商品文字及整列定位使用原图像素，屏内主体和文字区域使用0..1000
归一化位置；程序验证正面积和源边界后转换为原生守卫的左上右下数组。不得猜测旧数组
含义、交换坐标或自动裁掉越界部分来通过校验。

## 自动处理事实冲突

原照文字观察后，用一次独立事实阶段把原始用户陈述和包装证据合成 `resolved_facts`。
每项记录来源编号、approved/excluded/uncertain、理由及共同版本，所有原始陈述必须得到覆盖。
规划、方案审查、生成、实图审查和修复共同消费它，不再逐屏重复解释 raw facts。
原始输入仍保留。每个文字区域的 `fact_adaptations` 记录获准事实编号、替换理由和保留的
视觉机制；程序拒绝使用被排除或不存在的事实编号，但不会替模型编造事实或视觉判定。

产品物理身份与三拼等配料身份以清晰的原包装和实物证据为准；用户补充事实提供其余明确
授权的主张。直接矛盾的说法不进入新文案，保留原输入并记录采用依据。无法可靠判断时使用
真实的较宽表述，或返回明确的失败原因；流程中不得依赖操作员聊天选择或代为保存版本。

这不允许从配料推导未经支持的功效，也不允许把参考图的数字、检测报告和认证当作商品事实。
原照没有写出某项用户明确提供的主张，不等于直接矛盾。修正冲突配料不能连带删掉其他
已授权功效。对不适用的参考主张，应以当前商品真实事实保留载体和表达机制，并说明替换
依据；不得用通用原料列表抹去适用的购买问题，也不得为了验收复制不受支持的参考功效。

## 发布和验收

1. 工作区级试点开关默认关闭；原历史任务及其他复刻方式沿用原接入。
   关闭新创建开关后，已有新协议任务仍按其冻结协议恢复。出现问题时优先关闭该开关，
   不得用无法识别新协议的旧二进制接管仍在运行的新任务。
2. 本地回归必须覆盖元数据由程序绑定、通过模块不漂移、失败审查不变成 PASS、快照版本校验、
   有限修复和原始生成字节保留。运行完整 CI 后才构建、发布试点。
3. 使用同一组三张原商品照片及十二屏参考图，从普通页面上传或选择素材并点击生成。
   后台自动提交之后允许只读观察日志；禁止脚本调用分析/确认来代替页面、手改状态或现场改输出。
4. 检查真实排队和模型请求、同任务进度单调、页面刷新恢复、十二张不同原生尺寸输出、实际
   像素质量、历史记录及十二份签名原图下载字节哈希。
5. 记录调用次数、输入规模和总耗时。已知费用与估算、未知费用分开。单测、健康检查和方案
   READY 都不是成图验收。明确失败时保留原因与产物，不通过无限整组重跑掩盖失败。

当前文档记录试点设计，不代表实现、上线或十二屏真实链路已经通过。

## V2 的审查复用、中断与兼容

- `_visual_stage` 是精简视觉阶段的明确入口，阶段 MD、schema 和共享 `visual_policy.md`
  是规则来源。旧原生编排的内联 instruction/schema 仅为兼容接口，不混入新阶段请求。
- 复用键包括有效协议、阶段/schema/实际模型输入、商品与参考实际图片哈希、提案及文字/
  身份/事实适配绑定、事实版本、配置的模型及备用路由。原生编译派生的比例元数据不使
  未改变的视觉提案失效。变更任一依赖就重新观察受影响屏。
- 缓存保留原始模型响应及哈希，使用时再次验证 schema、绑定和判定一致性。真实 FAIL
  也保留，不允许对相同失败输入反复抽判定。拆屏修正后的第二次独立盲查仍须实际执行。
- 每份新成图做一次真实像素审查；修复产生新像素后再审查一次，不为确认已有 PASS 额外
  重抽一次。原生初稿/一次语义修复和原图尺寸要求保留，格式纠正/备用调用另记真实用量。
- 每次模型调用结束及有效阶段完成时保存私有快照、调用/费用摘要与逐屏进度；失败同样
  保存。显式继续会启动新的原生规划 session，保留前一份，并复用依赖仍然一致的阶段。
  不会把已经进入生图的执行快照改回分析，也不会人工改 PASS 或任务终态。
- 页面显示已规划/已确认屏数，中断时提供“继续处理剩余步骤”；刷新和历史使用服务端
  状态；有断点的继续操作保留进度高水位。存活分析有独立心跳，避免长调用被无更新
  超时误判。费用未知保持未知。
- 每次显式分析尝试受 `POLARIS_REPLICA_EXACT_ANALYSIS_TIMEOUT_SECONDS`（默认 1800 秒）
  和 `12 + 6 × 实际屏数` 的分析调用预算限制；格式纠错计入。继续时保留累计用量，已验证
  缓存不消耗新的模型调用。图片阶段仍沿用原生令牌与结果未知不重发的保护。
- R16 v1 的主文件和 11 份 MD 原字节封存在 `replica_exact_versions/v1/`，哈希仍为
  `ff3a1975dede71a0ba29673c1642c33e33f76df13d14404f0a893c5e12812b5f`。
  历史快照按版本选择原执行器，不静默迁移到 v2。v2 绑定阶段 MD、编译器、事实与布局
  辅助器、原生执行和生成适配代码；改动有效协议后须明确处理兼容。
- 工作区试点开关保持原范围；本次没有把其他 Skill 或所有工作区同时迁移。

本地 synthetic 测试只证明契约和用户路径的程序行为。生产发布及原十二屏普通页面真实
验收必须另有证据，不能由该文档或 CI 成功代替。
