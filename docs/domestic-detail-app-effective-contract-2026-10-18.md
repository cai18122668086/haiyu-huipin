# 国内详情：网站适配器绑定原生有效排版契约

## 修复范围

原生局部修订已经支持保留原方案并叠加有限的排版字段。网站预检此前未向模型提供实际有效契约，也没有要求模型区分“恢复原约定”和“修改局部约定”；生图适配器仍将签名请求中的契约与原始 `module.plan` 比较，因而会拒绝合法的新排版约定。

现在在原有的一次范围预检中，提供原生 `inspect-pair-review-contracts` 返回的有序双屏有效契约及其摘要。预检后每个原始修改项必须返回 `contract_effect`，同时返回明确的 `contract_overrides` 列表。原方案、用户原文、事实账本和审批文档保持原来的权威关系。

- `RESTORE_OR_PRESERVE_APPROVED`：原有效契约仍适用，无字段替换。
- `OVERRIDE_LOCAL_FIELDS`：必须绑定原始修改索引、选定屏幕、精确字段路径、当前有效旧值及替换值。
- 本阶段只允许原生共享 schema 列出的 12 个 `text_system` 叶字段。旧值包含 JSON 类型的精确匹配；重复字段、同值替换、空白、另一屏、事实、文案、职责、接缝和结构修改均不能据此获得授权。
- 已有原生叠加层时，必须读取其实际有效投影，不能回退为原始方案。

生图适配器只在双屏存在局部契约叠加时重新读取原生有效投影，比较完整契约及摘要；普通生成保留原比较方式。原生提示词、签名请求和原生审核继续使用同一个有效契约。此改动不修改原生 Skill 文件或 manifest。

## 验证与边界

独立修订测试走过当前租约及权限检查、一次原始范围模型结果、独立原生副本、真实原生请求编译、网站生图适配器、已接受原画布引用，以及重复准备不增加模型调用。测试使用合成素材与显式假模型，不证明真实图像质量。

类型检查覆盖全部 110 个应用 Python 源文件。负例覆盖旧值与 JSON 类型、其他屏幕、未知字段、事实或文案权限扩大、重复补丁、缺失判断、无对应修改项及已有有效值。国内主图、原生修订、报价与子任务、像素执行边界另行回归；缺少原始来源 ZIP 的校验必须明确记录为跳过。

本阶段仍是本地接线。`prepare_revision` 尚未接入对外付费的 `ImageProvider.execute` 流程，图片供应商调用为零。账号远端授权及可用性证据、实际原图/候选图观察及审核来源、文案与其他局部契约、连续修订与混合来源、公开 HTTP/UI 恢复链、历史版本分流，以及完整隔离服务和真实视觉验收仍需完成。不得把本阶段称为详情图 Skill 完整接入或全部需求验收。

正式 main 合并与服务器部署继续分别审批；本阶段不消费生产队列，不改动或重跑用户原任务。

账号本地配置检查已单独接入，见[新请求前账号配置检查](domestic-detail-revision-account-configuration-2026-10-18.md)；它不证明远端授权或余额。
