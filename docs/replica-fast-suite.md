# 一键复刻：独立快速版

状态：本地实现，未部署；2026-10-29 已进行一次快速 exact 真实接口测试，尚未进行同素材原版对照。

## 用户入口与隔离

一键复刻增加「生成版本：原版 / 快速」，默认原版。两种版本均可选择一比一模仿或风格复刻。草稿与历史恢复所选版本，切换版本会生成新的分析请求身份，不覆盖正在执行的方案。

只在分析请求显式传入 `replica_speed: fast` 时进入新路径。原版默认字段不进入旧请求身份计算，原任务恢复和重试继续使用原实现。普通 reference_remix 作业配置不增加新的默认字段；快速作业用独立 Skill ID 和方案哈希绑定版本。

原 Skill 目录、manifest 和 exact-compact-v15 协议依赖保持不变。原协议哈希为 `67de9f26f2928a566acc92d1083e6fe2fa907710e7fd4eb46ed85e47ee03fe95`，回归测试锁定该值。

## Skill 副本

- `aurora-ecommerce-reference-remix-fast` 完整复制自 `aurora-ecommerce-reference-remix`。
- `all-category-style-benchmark-still-fast` 完整复制自 `all-category-style-benchmark-still`。

副本保留原始参考资料、schemas 和 scripts。新的 SKILL.md 明确快速版由独立网站控制器执行，不运行副本里的旧审计 CLI。规划只装载当前方式所需的视觉参考章节；模型不会逐轮读取全部执行手册。两个副本各有独立 manifest，可运行 `backend/scripts/generate_replica_fast_manifests.py` 更新新版本锁；该脚本不会更新原 manifest。

## 快速执行契约

1. 一次模型请求同时完成商品身份、授权事实、参考分栏/拆屏、共享风格与全部逐屏方案。共享内容只输出一次，程序组合每张完整提示词。使用独立 `replica_fast_suite` profile，不跨渠道回退增加规划轮次。
2. 本地校验参考覆盖、顺序、分栏不重叠、分屏边界连续和单屏尺寸。长图按物理屏幕裁切参考输入；交付图片不做本地排版、拼贴、文字覆盖或拉伸。
3. 创建一个套图作业，单套最多同时执行 20 张，并遵守更小的 worker 并发设置；少于 20 张时同时提交，超过时任一张完成立即补位。数据库作业行锁和活跃租约计数让重复 worker 共享同一套 20 槽位。既有配额、共享图像准入和积分预留约束保持不变。每屏独立生成；风格快速版不合并相邻双屏。
4. 每张图只提交一次付费生图请求，直接保存供应商原始字节，检查能否解码、比例误差不超过 1%。继续请求最短边 1024 的画布；验收接受最短边至少 1024，或原始短边至少 768 且总像素至少 150 万的供应商自动画幅。非标准画幅追加独立空白画幅参考，不对最终图片补边或放大。低清和比例错误仍然拦截。
5. 无独立方案审计、无成品 AI 审计、无自动审美返修。状态为 `STRUCTURALLY_VALIDATED` / `NOT_REVIEWED`，不伪造视觉 PASS。

一次支持最多 20 张参考图、60 个拆屏结果；单屏最长边不超过 8192，总像素不超过 2000 万。模型未完整输出方案、几何非法或长图未合理拆开时停止生图，保留调用回执供明确重试。快速模式不保证与原版效果完全相同，需要真实样本评估。

## 进度与恢复

私有 `_fast_plan`、`_fast_analysis_receipt`、`_fast_invocations` 记录方案、来源哈希、用量与每屏调用状态，不在文档接口中返回。提交前先持久记录 invocation，未知提交或下载结果停止重复提交。已知拒绝只能由新重试作业重新调用；成功屏幕按现有失败项重试规则保留。

供应商原图先独立保存，再交由通用执行器发布素材。因此最终交付存储失败后，重试可复用已经返回的原图，网络调用计为零，不重新规划或生图。此前仅因尺寸不达旧门槛而拦截的原图，也会在明确重试时先按当前策略校验；通过则复用，仍不通过才允许新重试作业生图。来源、哈希和归属校验继续执行，未知提交结果仍禁止重复请求。历史任务继续使用创建时的 Skill ID、方案和事实。

## 真实接口测试：2026-10-29

使用用户提供的 3 张身体乳商品原图、8 张对标图和卖点文本，通过独立本地数据库的上传、分析、确认和作业执行接口测试。使用本机已有的真实规划/生图通道，未连接生产数据库、支付或生产任务。私有输入、回执和原图仅保存在忽略目录 `backend/.data/replica-fast-body-lotion/`。

一次整套规划耗时 72.28 秒，识别 8 屏；8 次生图均返回原图，上传至最后一张返回 529.38 秒。无二次 AI 审计，无自动重绘。首个原始结果在 150.25 秒返回；这不等同于页面首次可交付时间。

4 张原图通过技术尺寸检查，另 4 张短边为 887 至 960 像素，被 1024 门槛拦截，作业为 partial。该通道当前不发送 size 参数，实际返回尺寸需要与快速版交付策略协调，不能把已经生成的图片误当成没有结果反复提交。

实测还发现真实 provider 经过公共路由后缺少结果来源标识，导致通过技术检查的图片被默认 mock 来源过滤。快速 provider 现统一附带 provider/model/pricing 身份；真实路由回归测试增加了可交付素材断言。已使用同一批保留原图，在禁止任何规划/生图调用的本地恢复运行中成功发布 4 张素材，新增外部调用为零。此修复不改变原版 provider。

人工查看结果：总体版式、中文文字与蓝白/粉色风格可继承；第 3 屏额外加入参考画面没有的商品瓶；第 5 屏出现没有依据的对照曲线。参考中的价格、赠品和实验百分比没有照搬。商品原图中存在包装差异，后续应强化主商品身份选择，避免混用包装细节。这些是本次实测观察，不是运行时新增审计步骤。

第一轮观察：首批最快 76 秒、最慢 139 秒，第二批最快 103 秒、最慢 230 秒，批次屏障存在可观空等。后续按用户确认已实施 20 张滚动并发与原始尺寸适配；现有模型、画质、规划和生图提示词、两个快速 Skill 内容保持不变。无数据图表、商品是否出现及主身份锁定仍为可选的后续质量优化方向。本次未运行同素材原版，不能声称与原版质量相同。
