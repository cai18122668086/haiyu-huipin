## 本次生产调查结论

2026-11-06 北京时间 16:57:36 创建的快速复刻有 10 个图片子任务，本站在 16:57:55 结束任务。

绘品调用的聚合服务对外原任务 GET 都显示 `failed / supplier_request_failed`。进一步查看聚合服务的持久记录发现：

- 10 次请求实际路由到 Agent3，每个请求只提交过一次；没有查询失败计数。
- 供应商原始 HTTP 状态全部为 202，响应体完整读取，均为 424 字节。
- 诊断均为 `phase=upstream_pending / errorClass=task_not_final`。
- 聚合任务实际处于 `reconciliation`，而对外任务接口显示为 `failed`。
- 聚合服务没有保存可用的供应商任务编号或 `status_url`，因而没有进入供应商原任务轮询。
- 16:58:26 至 16:59:04，10 个聚合任务分别收到并持久保存了 `image.completed` 通知。
- 通知没有供应商签名，仅有任务专属回调 URL 的认证，不足以直接作为图片成功交付或结算依据。通知中的真实供应商任务编号与 HTTP 跟踪编号不同。

当前代码的 202 解析只接受指定字段及 `queued/running` 状态；不符合时返回不确定结果。后续任务处理将该结果结束为 `reconciliation / supplier_request_failed`。回调仅唤醒“已绑定相同供应商编号且仍在 queued/running”的任务，本批任务已不满足条件。

因此，已定位到聚合网关的异步接单解析及后续恢复链路异常，不能将此次问题定性为供应商明确拒绝或未执行生成。

限制：本批原始 202 响应正文对应的临时加密文件已被清理，只剩摘要与描述信息，无法进一步确定是哪个响应字段不符合解析条件。使用现有 Agent3 Base URL 查询回调中的真实任务编号仍返回 404；可能需要受理时返回的原始 `status_url` 所指入口，不能猜测其他入口或重新生成来验证。图片尚未找回或校验。

供应商文档要求保存并优先查询受理响应中的 `status_url`，并明确不同入口不一定共享任务；见 [官方异步任务与状态文档](https://www.shyfai.cn/)。最初只读调查没有修改聚合服务。

## 后续复现与网关发布

独立合成请求捕获了真实 202 回执：`status=processing`、`stage=queued`，`request_id/id` 是回调 UUID，而 `task_id` 是 `imgbill_…`；`status_url` 为指向该不透明任务编号的相对路径。旧网关的状态白名单不包含 `processing`，因此复现相同的 `task_not_final → reconciliation` 故障路径。按回执中的原始 `status_url` 查询，该合成任务已经完成，不能仅用回调 UUID 拼接查询地址。
