## 本地修正

- 网关返回带正规 `image.task` 终态回执的 HTTP 502 时，先保留为已接单，再按原状态处理；允许有授权的恢复流程只用 GET 查询同一个原单，不重发 POST 或切换模型。兼容现有 `failed` 加禁止替代的说明，也能识别显式 `reconciliation`。
- 有疑似接单证据但缺少正规回执形状的非成功响应单独记录为不确定；重启后也不能误当成可查询原单，不能用其中的路由错误触发重新生成。保留脱敏供应商诊断，无法确认时按失败关闭。
- 旧版限流日志若已经记录任务编号，不允许再走限流重发；非成功 HTTP 响应里的图片字段也不会被当成可交付结果。
- 任务摘要给出可操作的客服指引：提供本站任务编号核查原单。不展示供应商回执或原始错误正文。
- 复现创意生图待核查时，即使其错误摘要指向另一个子项，原版重试接口仍返回 201 并创建新任务。现按整组子项阻止重试和复制，任务列表与详情不再提供这两个操作；服务器拒绝发生在新任务入队和积分预留之前。已知未接单的失败不受此限制。
