## 行为与边界

对已接受的 8/10/12 屏详情，可先读取当前方案、成图及模型路由绑定的费用预留，再明确授权一次独立 `domestic_detail_review` 任务。请求绑定原详情、方案版本、C4 与存储原图、最终审阅指纹、商品事实权威、当前源码和报价。公共执行器继续承担排队、租约、取消、费用与结算；详情模块承担审核语义和原始证据。

新任务只允许一次整页模型请求、零图片请求、零新生图资产。原生 `fork-campaign-review` 在新任务工作区复制已经核验的 session；原 session、成功图片、双屏母版、原审批和原交付记录均不改写。长图仅在独立审核工作区组装为可选预览。原生观察校验器和正式交付命令未放宽。

`aurora_detail_campaign_audit` 使用已报价的实际模型路由。失败不自动切供应商或重试。输入含原商品参考、按序的全部接受单屏和原生预览；逐帧保留实际模型所见字节与哈希，发起审核前及报告回读时逐窗口核对预览与接受单屏的 RGB 像素完全一致。原始 UTF-8 回复、解析结果、请求/响应回执、用量、原生审核快照和报告分别保存。审核 schema 从原生动态要求投影，不能只检查静态清单。

缺观察、未知观察、数字冒充布尔值、PASS 与失败矛盾、原文不匹配或图片绑定变化均拒绝质量采纳。原生审核还会拒绝重复模板证据；拒绝结果和真实观察仍保留，不补 pass、不自动重绘。

## API

- `GET /jobs/{source}/campaign-review/quote?final_review_sha256=...`：当前来源、路由和费用预留的指纹。
- `POST /jobs/{source}/campaign-review`：明确授权、费用预留、报价与最终审阅指纹；HTTP 幂等重放返回同一个独立任务。
- `GET /jobs/{review}/campaign-review/report`：验证本次原始模型输入、回复及原生快照后回读原报告。
- `GET /jobs/{review}/campaign-review/preview.png`：回读同一绑定的预览，private/no-store。

以上位于 `/api/v1/workspaces/{workspace_id}` 下并验证工作区权限。费用预留是估计和额度预留，不承诺供应商实际费用上限。原任务有活跃审核、数据库记录运行/结果未知、请求无响应，或回执/原文损坏时，必须先核对原请求，不能以新 HTTP key 再付费。通用 retry/clone 也拒绝该审核任务。
