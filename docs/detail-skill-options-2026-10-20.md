页面只使用“快速 / 精美”两个名称。用户可在创建任务前选择；已有任务和重试保持创建时的选择。

- 快速：现有 Aurora / WEBSITE_DIRECT_V2 路径，原有策划、相邻双屏画布、固定切片和审核不变。本次没有继续恢复其原版深度策划。
- 精美：独立的 `xinghe-ecommerce-detail-domestic-4` 源码锁和任务路由。上传的 ZIP 内 22 个文件全部逐字节保存，包括原 frontmatter 和 agent 配置；没有改写原文。独立 manifest 记录原 ZIP 哈希和完整文件哈希。

## 对齐主图的接入边界

采用仓库固定的 skill 源码，调用前验证来源；模型读取完整 SKILL.md 与全部参考文档。网站只转换输入、持久化完整策划与逐屏执行内容、确认计划、调用配置好的供应商、保存产物与记账。

新包本身没有主图使用的 Python Harness，不能套用主图的执行脚本或六图合同。精美路径按原包保留需求排序、商品类型、购买决策、页面策略、首屏方向、模块计划、视觉节奏、统一风格、设计强度、商品身份/物理锁与逐屏任务表。`image_prompt` 由模型按原文提示词合同完整编写，在确认与生图时原样传递，不再用旧详情模板重写，不施加旧模板的整鞋出镜比例或拼板禁令。

网站必要适配：

1. 本机 PowerShell helper / 聊天内置生图由现有网站供应商网关替代，继续使用网站密钥、限额和对象存储；不运行下载包中的命令。
2. 用户确认完整方案后生成，符合网站现有任务确认交互。每页独立 3:4 请求，支持 1–12 页。按站点并发上限分批，每批间隔 3 秒错峰发起。
3. 不运行自动画质复审、自动重绘或双屏切片。所有成功生成并通过文件完整性/规格验证的图片直接交付。保留供应商原始字节，不在本地拼图、叠字或重采样。
4. 网站界面、方案文档和下载文件名不显示 skill 名称、作者、模型或版本。每页执行提示词仅显示指纹，指纹参与整份方案确认，防止隐藏执行内容在确认后变化。

### 已核实的渠道与错误来源

- `https://api.ooapi.cc` 的公开站点标题为“玩转AI - AI API Gateway”，即用户所说的玩转。此前把接口域名和品牌当作不同渠道，以及要求用户新增文字模型渠道的结论均已撤回。
- 当前网站配置里保有三个玩转规划账号，逐个读取模型列表均返回 HTTP 200，并都列出已配置的 `gpt-5.6-sol`。
- 旧详情发布脚本把主 API 的整个 `POLARIS_PROVIDER_FAILOVER_API_KEY` 多账号字符串复制进了单个 `POLARIS_ANALYSIS_API_KEY` 字段。服务器内布尔比较已确认：详情字段等于整个账号池，不等于其中任何单个账号。这是此前 HTTP 401 的真实原因，不是三个玩转账号均失效。
- 另一次沿用旧主字段的 Tengli 诊断返回 `model_not_found`，原因是该令牌属于 image 分组。它仅证明那套字段不适用于文字规划，不能据此断言项目没有现成文字模型配置。
- 修正后继续沿用玩转识别/策划、Artflow 生图。隔离进程从现有玩转账号池取出一个单独凭据，仅在内存持有；保留全部历史请求和未知费用记录，不覆盖原回执。
