# 国内详情原生规划单次派发与原始回执（C5，本地候选）

国内详情曾在一次逻辑审核调用内部切换到另一条供应商路由，导致外层“只调用一次”仍可能产生两次付费请求。配置以备用路由优先时，审批与用量中的模型还可能记录为名义主模型。本候选把原生详情的实际路由选择提前到持久化请求之前，并把单次传输、原始回复和后续复用绑定在一起。

本阶段在 `codex/domestic-detail-contract-repair-20261017` 本地实现。main 保持 `785ff55`；没有推送、合并或部署。本阶段离线技术验证已通过；真实供应商、画面及完整发布验收仍待后续完成。

## 范围与边界

覆盖 `aurora_domestic_intake`、`aurora_domestic_detail`、`aurora_domestic_plan_repair`、`aurora_domestic_modules_completion`、`aurora_domestic_campaign_completion`、`aurora_detail_pair_audit`、`aurora_detail_identity_audit` 七种原生详情规划/观察阶段。

公共网关继续管理 HTTP 传输和供应商用量；详情模块管理绑定、原始回执和恢复判断。非详情请求继续走原有有序路由切换。国内主图的生成与审核策略保持现有行为，公共执行器仍负责租约、取消和费用结算。

## 调用与恢复

- 派发前固定 provider、route、请求模型、endpoint 指纹和凭据配置指纹。凭据和原始 URL 不写入回执；请求绑定与实际选定路由不一致时在发出 HTTP 之前停止。
- 原生详情每次逻辑调用允许一次 HTTP transport；并发请求各自记数，不从共享计数器差值推测次数。
- 供应商报告模型单独保存。请求模型与报告模型不混为一个字段；缺失报告时不推测供应商内部解析到了哪个模型。
- 初始规划、模块补全、整组补全和显式修复保存独占请求 marker、完整语义输入、提示词/schema、素材哈希、Skill/runtime 指纹及原始 completion。其 wire idempotency key 由完整绑定派生。
- completion 已知且完整时复用原结果，保留原始用量。相同原调用在单个任务的汇总中只出现一次；明确的新修复上下文使用另一绑定与请求键，并受现有阶段预算约束。
- 请求结果未知、原始 completion 丢失或原始文字/解析结果冲突时停止自动补发。失败重试沿同工作区、相同配置的血缘检查原始未知阶段。已有合法候选的恢复仍作为已保存创作输入处理。
- intake 与逐屏审核同样绑定选定路由。intake 事件绑定源任务与文件；逐屏审核保留 C4 的原始 request/response/UTF-8 回复重建及原生像素血缘核验。

职责代码为 `backend/app/domestic_detail/planner_dispatch.py`、`planning_calls.py`，以及现有 `intake.py`、`review_provenance.py`。协调器只负责组装请求、调用和结果交接。

## 验证记录与限制

本阶段只使用显式合成数据与内存 HTTP transport；离线启动器拒绝外部 socket 和私有 .env，使用独立临时 SQLite/存储，未继承供应商凭据。C 盘仅存本次临时测试数据；结束后先把全部原始文件归档到 D 盘并逐成员读回核验 SHA-256，再清除本次临时目录。
