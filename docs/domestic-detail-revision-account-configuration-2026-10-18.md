# 国内详情局部修订：新请求前检查实际账号配置

## 问题与行为

原有路由指纹会对凭据做哈希，空凭据也能得到格式合法的指纹。因此，核对报价指纹不能证明当前实际图片和审核账号已经配置完整。

新增的 `revision_accounts.configured_revision_accounts` 读取网关实际的 `_image_routes` 与 `_ordered_routes` 选择：图片必须是唯一的实际图片路由，审核必须是原生模型实际选择的首路由。检查非空凭据、模型及合法 HTTP(S) 地址，再重建指纹并与实际选择核对。只记录配置证明和指纹，不记录凭据、明文地址或供应商异常详情。

`prepare_revision` 在现有的一次范围模型请求之前调用这项检查。检查发生在原始请求发送标记写入之前，并把结果绑定到独立子任务的原始意图和报价。缺少图片或审核配置时，不产生这次模型请求或其费用。显式离线网关继续作为合成测试运行。

读取既有的原始付费范围结果时不再次执行新增的账号检查，仍保留既有来源、租约、路由绑定及用量去重规则。配置检查不会为结果未知的请求创建第二次调用。

## 证明范围

这项检查不向供应商发请求，不证明远端授权、余额、模型权限或实时可用性。保存的记录明确包含 `remote_authorization_verified=false` 与 `remote_balance_verified=false`。实际供应商及完整隔离验收仍需建立相应证据。

测试覆盖真实网关配置选择、缺少凭据、无效地址、空路由或多路由、选择与指纹冲突、审核轮换与独立图片账号、发送标记前拒绝、原始结果恢复与账单去重。独立原生副本测试同时核验来源任务不变、配置证明归属及重复准备不增加检查或模型调用。

本阶段不改变国内主图、共享网关传输策略、原生 Skill 或其 manifest；不新增对外付费的 `ImageProvider.execute` 局部修订入口。原图/候选图观察、审核来源、其他局部契约、完整 HTTP/UI 恢复链和真实视觉验收仍需完成。
