# 国内详情单次范围预检与独立原生准备（本地候选）

父提交 `bdf813acffdeebd3cfc472fe0d8c8b53c9e9e647` 已完成独立修订子任务构造。本候选实现语义范围协议、单次模型调用和原回复恢复，以及通过公用 attempt 记录核验后创建独立原生分支的准备函数。该函数仍未接入图片执行器，也未开放公开执行端点；完整修订业务尚未验收。

`revision_protocol.py` 绑定真实修改原文、每项 change_only、原生身份与原事实账本、完整批准方案、目标双屏和来源指纹。模型必须逐项判断身份、事实、受众、整页风格、屏幕顺序，以及另一屏和其他屏幕的保留义务。五个 false 只是待核验的用户声明。LOCAL 必须同时具有全部明确的局部、保持和非新增主张结论；缺失、未知、越界或自相矛盾均不能通过。事实引用逐项比对原始 id 和完整文本，拒绝把 DEFERRED、EXCLUDED 或模型新编的内容变成可表达事实。语义判断不构成画面观察或质量通过。

`revision_scope.py` 使用独立的原生模型阶段 `aurora_detail_revision_scope`，最多一次实际 transport、4096 输出 token；服务端错误、超时和坏消息均不转备用账户、不发格式修复调用。实际网关接收绑定的 schema 和原文上下文。先独占记录原请求，再把原始模型结果原子保存到 owned journal，随后记账和生成派生回复。重复执行按原绑定恢复，不改变上下文或账户重发。原请求已存在而没有完整 journal 时停止。派生原文损坏可以从原 journal 零模型恢复，损坏字节先保全；原 journal、请求或结果相互冲突时拒绝替换。

计费区分经过验证的 HTTP not_sent 和可能已发送。前者必须是原路由的零 transport、无响应、明确错误及未调用标志，记录零请求、零费用和独立诊断，不写入会按次数结算的 planner 列表。未知、坏回复或无效传输证据保留原请求并按原单次模型预留处理。重复记账核对绑定与原结果，只登记一次。两类情况均由现有账本计算函数验证；这些是离线模拟用量证据，不代表真实供应商账单验收。

`revision_runtime.py` 核对新任务、工作区和原用户的当前写权限、公用 attempt/item、原幂等键、租约截止时间、取消状态、确认方案、原审批、当前账户路由和报价单价。真实调用还要求精确的新任务七次请求预留。原编译 input/identity/plan 字节与会话先核验并缓存，防止核验后把另一份输入复制进去。单次模型费用超出预留时先保存和记账，再停止后续准备。

预检通过后才向新目录原子写入原输入、身份、方案、来源会话及新意图，使用新任务自己的 generation binding，并调用原生 `fork-local-revision`。原任务和原费用保持原样，新分支固定等待人工最终审阅。发现前一子任务意图缺少编辑底图验证器需要的顶层 source_generation_binding_sha256，现从已确认报价显式导出并在执行前核对。两条来源链进一步编译首个原生图片请求，验证实际编辑画布对应原双屏及原调用/像素谱系；该阶段没有调用图片供应商。
